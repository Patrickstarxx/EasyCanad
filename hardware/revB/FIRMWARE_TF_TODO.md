# TF 日志功能后续固件工作（本轮不修改代码）

本轮只提供硬件。现有 v6 固件仍只通过串口输出日志，插入 TF 卡不会自动开始记录。

## 引脚约定

| 功能 | SuperNano 引脚 | 接口侧电平 |
|---|---|---|
| TF CS，低有效 | D10 / SS | 经过 U3 转换为 3.3V |
| TF MOSI / CMD | D11 / MOSI | 经过 U3 转换为 3.3V |
| TF MISO / DAT0 | D12 / MISO | U4 第四路转换为 5V；D10 高时输出高阻 |
| TF SCK / CLK | D13 / SCK | 经过 U3 转换为 3.3V |
| 可选插卡检测 | D6 | J8.10 为无源触点，插卡接 GND，R13 上拉到 5V |

A0、D2、D3、D4、D5、D7、D9 的现有分配不变。D0/D1 留给模块 USB 串口。

## 实现要求

1. 上电先将 D10 配置为输出并置高，再初始化 SPI。硬件 R17 也将它上拉，确保复位期间不选中卡。
2. 使用 SPI 模式 0，初始化时钟不超过 400kHz。首轮联调工作时钟以 1MHz 起步；在最终线束、供电和卡型号上测量后再提高。
3. D6 为低有效插卡信号，需要去抖。没有接检测触点时一直为高；不得把“无检测触点”误判成整个系统故障。可提供关闭插卡检测的配置。
4. SuperNano 的 D13 同时连接板载 RGB 数据输入。SPI 使用期间禁止运行 NeoPixel/RGB 驱动；尤其不能用长时间关中断方式更新 RGB。检查 SCK 实际波形和 RGB 的附带响应，并把其耗电计入 5V 预算。
5. 先评估静态 SRAM、最大栈深度和库缓存。ATmega328P 只有 2KB SRAM，文件系统通常还需至少一个 512 字节扇区缓存；不能直接加入多扇区队列或动态字符串。
6. **写卡最坏延迟必须与控制周期隔离。** 常见 SD/FAT 写入、分配簇及同步可能长时间阻塞。现有控制循环和输入超时逻辑不允许因为日志写入暂停；禁止直接在每个控制周期调用同步 `println`/`flush`。采用可证明有界的状态机、预分配文件和丢弃日志策略，并实测满卡、坏卡、慢卡、拔卡、掉电情况。若所选库不能满足时限，应改用独立日志协处理器，而不能宣称普通同步 SD 库已满足控制实时性。
7. 保存现有日志原始字段与版本、时间戳、开机事件、配置快照和丢帧计数。掉卡、写失败或日志缓冲满时停止/丢弃日志，并让控制主循环继续运行。
8. 建议先支持常见 SDHC/FAT32 卡，明确容量和格式限制；不能把 SDXC/exFAT 兼容性当成默认能力。
9. 写入结束后在地面执行有界的关闭/同步流程。现有板没有掉电保持供电，470uF 是舵机电源去耦，不能保证 FAT 掉电保存。

## 需要形成的测试证据

- TF 关闭/开启时的最大控制周期、舵机脉冲抖动和 PWM 捕获丢失情况。
- SRAM 峰值、最低剩余栈空间、日志吞吐量和丢弃计数。
- 每种受支持卡的写入延迟分布和最坏值，包含满盘及碎片化状态。
- 强制复位、断电、插拔、写错误时的控制连续性与日志可读性。

以上工作完成前，本硬件交付只代表预留 TF 接入能力，不代表已实现板载飞行日志。
