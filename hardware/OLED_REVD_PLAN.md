# Rev D 规划：移除日志，增加 OLED 状态显示

日期：2026-10-26。基于已保存的 Rev C（`8a09759`）和当前固件。**本文件为规划，尚未修改原理图、PCB、固件或生产文件；Rev C 仍是带 TF 接口的历史交付版。**

## 采用的方案

取消 TF/SD 记录硬件和机载连续串口日志，改为外接 **0.96 英寸、128×64、SSD1306、I²C OLED 模块**。模块须同时支持 5V 供电和与 5V Nano 的 I²C 电气连接。参考 Adafruit 326 当前 5V-ready 版本的电气要求，不把普通裸屏或仅标称“5V 供电”的模块直接视为等效器件。

屏幕默认只显示状态，不增加菜单、编码器或按键操作；保留原有标定按钮、地面配置跳线、USB 参数配置和 EEPROM 保存。屏幕通过短线连接，不将其机械尺寸叠加到载板外形；其固定孔不在尚未选定实物模块前假定。

## 当前代码中需区分的三件事

| 功能 | 当前情况 | Rev D 决定 |
|---|---|---|
| TF 文件记录 | Rev C 有接口，但固件尚未实现写卡 | 删除接口及后续实现计划 |
| 连续串口飞行日志 | `FlightLogger.h` 产生 C/R/D 数据流；主循环每 5ms 尝试记录 | 移除连续采样记录、回放同步和日志启停命令 |
| 配置、标定和状态应答 | 与日志共用缓冲和发送函数；上位机依赖配置回读 | 拆出独立串口协议并保留；按请求回复，不连续记录 |

EEPROM 中的参数和风标零位继续保存。这属于设备配置，不属于本次移除的飞行日志。保留 `missedControlPeriods`、`maxControlIntervalUs` 等运行诊断计数，供显示及台架验证使用；不写入文件。

## 硬件变化与引脚

| 项目 | Rev D 处理 |
|---|---|
| J8，原 TF 2×5 接口 | 替换为 1×4 OLED 接口；位号沿用 J8，针数和用途改变，不能沿用旧线束 |
| R13 | 删除，D6 插卡检测释放 |
| R14/R15/R16 | 删除原 SPI 串阻 |
| R17/R18 | 删除原 TF 片选上拉、时钟下拉 |
| C4 100nF | 保留并移到 OLED 接口供电脚附近 |
| 新增 OLED 去耦 | 接口附近增加 4.7µF；模块自身近端去耦仍保留 |
| I²C 上拉 | 预留两只 4.7kΩ 到逻辑 5V 的焊位，默认不装；按模块原理图确认上拉电压及等效阻值后定装配版本，避免不同电源上拉混接 |
| A4/A5 | 当前在载板悬空；新增为 SDA/SCL |
| D6、D10～D13 | 释放，不再接 TF 功能；不因本次规划新增其他负载 |

J8 新针序由载板定义，不假设与市售模块的针序一致，按名称接线：

| J8 针号 | 信号 | Nano 插座连接 |
|---|---|---|
| 1 | GND | 公共地 |
| 2 | +5V_LOGIC | JP1 后的逻辑 5V |
| 3 | SCL | A5，JN2.4 |
| 4 | SDA | A4，JN2.5 |

地址以 7 位形式在配置中明确指定，默认 0x3C，兼容选配 0x3D；不是运行中循环扫描总线。不同驱动 API 的地址表示方法须按其文档转换。模块应有上电复位功能，使四线连接成立。

保留 SuperNano 的三排 23 孔准确插接几何、J3 俯仰接口供 5V、PWM 输入/输出分组、按钮/跳线分区、Q1 反接保护和 JP1 USB 供电隔离方式。OLED 不从 GPIO 取电，载板不增加 3.3V 稳压或转换电路。短线以不超过 50mm 为初始布局目标；逻辑电源预留 100mA 显示支路预算，这是设计预算而非模块实测耗电。

删除 TF 区后重新压缩布局，目标不扩大 Rev C 的 45.72×40.64mm 轮廓；最终尺寸在布线、安装孔和手焊间距复核后确定，不把缩板目标当作已完成尺寸。

## 显示内容

采用 16 列×8 行的字符界面，优先使用英文缩写和数字，中文说明给出字段含义。128×64 单色完整帧缓冲需要 1024 字节，因此默认采用 U8x8 字符/字模方式，避免在 2KB SRAM 上保留完整像素帧。Wire、驱动状态和字符串仍占 RAM，不能理解为整个显示功能零内存。

| 行 | 示例 | 实际含义 |
|---|---|---|
| 1 | `RUN  ACTIVE` | 地面/运行状态及当前控制状态；异常优先 |
| 2 | `AOA    +12.3deg` | 已校零、滤波后的相对风标角；不是未经修正的 0～360° 原始读数 |
| 3 | `CMD    -05.0deg` | 逻辑舵角指令，不是舵机实测位置 |
| 4 | `SERVO   1444us` | 输出脉宽指令 |
| 5 | `THR     62%` | 有效油门通道的归一化值 |
| 6 | `RC OK MD OK` | 俯仰、模式通道有效性 |
| 7 | `CAL OK LAW 1` | 标定状态、控制律编号 |
| 8 | `SYS OK` | 最高优先级故障/标定进度/运行诊断 |

示例布局见 [OLED 界面预览](plans/revD_oled_preview.svg)，其中数值仅为示意。输入失效时相应数值改为 `--` 并给出状态，不用上次有效值冒充当前数据。速度模型如后续显示，必须标记 `EST`，不得标作实测空速。

GROUND 可显示“等待标定、采样中、保存成功/拒绝”等进度，仍按当前 D4 长按逻辑操作。屏幕不新增参数修改权限，不改变 D5 的上电锁定规则；RUN 不能通过显示功能进入配置。

## 显示调度与故障处理

现有 `CONTROL_PERIOD_US=5000`，控制目标为 200Hz。显示数据以 **5Hz 为初始更新目标**，只更新变化字符；控制运算、输入捕获和舵机输出优先。初始化、清屏、字符发送均需分批完成，不在主循环调用一次阻塞整屏刷新的例程，不使用显示动画和 `delay()` 等待。

一个完整的 1024 字节像素帧，即使按 400kHz、每字节 9 个时钟估算，纯数据也约需 23ms，已超过多个控制周期；降低“每秒刷新次数”不能消除这一次阻塞。

显示驱动按“字模生成”和“发送服务”拆开，默认规划 **前台软件 I²C、约 100kHz 起步**，保持中断可用；使用带 ACK 检查、时钟等待上限和失败退出的传输适配层，不默认认为库自带软件 I²C 已满足这些条件。每次发送服务最多一个小事务（从不超过 8 个数据字节起步），根据距下个控制时刻的剩余时间决定是否执行。目标每次服务不超过 1.5ms，正常及故障路径都要实测；达不到则缩小事务或暂停 RUN 显示，不能拖延控制。

选择此前台方案，是因为 AVR Wire 的 STOP 等待可能发生在 TWI 中断内；仅设置超时不能自动证明接收机捕获和舵机脉冲抖动合格。若实施时改用硬件 Wire，必须锁定支持超时的 AVR core、显式启用超时和错误检查，并单独验证中断内最坏等待；默认零超时不可接受。无论使用何种后端，都不能在一个显示任务内连续累积多次超时。

屏幕不接、地址错误、NACK、SCL/SDA 异常时，结束当前传输并禁用本次上电会话的显示服务，不在 RUN 持续重试或复位 Nano。显示只是控制结果的只读消费者，不参加控制律计算。重新初始化或总线恢复只在下一次上电或受控 GROUND 维护流程执行。

## 固件及上位机改动清单

| 文件/区域 | 后续实施内容 |
|---|---|
| `EasyCanad.ino` | 移除 `queueLog()` 和完整 `ControllerMemory before` 日志副本；在控制输出后更新精简显示快照，空闲时执行有界显示服务及串口应答服务 |
| `FlightLogger.h` | 将配置和事件回复拆到新的 `SerialProtocol.h`，移除运行日志编码/重同步；不能直接删文件而留下串口和标定调用 |
| `FirmwareState.h` | 删除日志序号、丢帧计数、连续记录开关等专用状态；重新预算串口应答、显示字模、驱动及栈占用 |
| `SerialConsole.h` | 保留 `status/set/save/defaults/run`；删除日志启停语义，旧 `log` 命令回复不支持；保留 E 事件和按请求的 C 配置回读，不再产生 R/D 运行流 |
| `CalibrationStore.h` | 将 `metadataPending/logResync` 依赖改为独立的配置应答/显示状态通知，保持原 EEPROM 格式和标定规则 |
| 新 `DisplayStatus.h` | 只读快照、数值有效性、告警优先级、变化字符、初始化及传输状态机；字库放 Flash，不用动态 `String` |
| `tools/model_profiles.py` | 当前依赖 `log stop/start` 并等待 LOG_OFF/LOG_ON；同步删除这些握手，避免移除日志后参数上传卡住 |
| 新 `tools/device_protocol.py` | 从 `tools/flight_log.py` 提取配置解析，保持 C/v6 回读兼容；机型参数工具不再导入日志工具 |
| 日志采集/回放工具 | 从当前使用入口移出，历史工具、旧文件格式和测试夹具保留为历史资料；不把旧捕获命令继续宣传为新固件功能 |
| 构建、测试及说明 | 增加并固定显示依赖；更新 Nano 两种 bootloader 构建、串口配置测试、显示故障测试；旧日志测试迁移，不直接删除其覆盖的控制行为 |

`ControlCore.h` 的 packed 字段布局同时服务配置/旧回放；本次不借移除日志擅自改动配置存储格式或控制律。用户既有 EEPROM 参数、v3 标定和机型 JSON 继续兼容。

## 实施顺序与完成条件

1. 从 Rev C 创建独立 Rev D 工程，修改接口、删除 TF 电路、重排布局；保留旧版及原始 Nano 孔位来源。
2. 更新中文原理图、OLED 针脚表、BOM、系统电路示意图和 Gerber，逐针验证 A4/A5、供电和保留接口。
3. 在后续明确的固件实施中拆分串口协议、移除连续日志，再加入显示；本轮规划不改可执行代码。
4. 在 Nano 实物上验证无屏正常启动、屏幕正常更新、断开/错误地址/总线异常；同时测控制间隔、接收机脉宽捕获及舵机输出抖动，与不带显示的基线比较。
5. 验证 USB 配置、EEPROM 保存回读、D4 标定、GROUND/RUN 锁定、输入失效和舵机限位没有回归；确认串口不再产生连续 R/D 数据。
6. 检查编译 Flash/SRAM 和实际栈水位，目标至少保留 512B 经最坏路径实测的栈余量。检查 OLED 全亮与舵机动作时供电，重新跑 PCB DRC、网表和插座钻孔检查。
7. 将已验证 Rev D 文件及迁移说明保存到 GitHub，清楚区分“规划”“文件检查完成”和“实物验证完成”。

本规划未指定屏幕模块的最终采购型号或新 PCB 最终尺寸；已给出默认功能规格、接线和实施约束，后续可据此继续设计。
